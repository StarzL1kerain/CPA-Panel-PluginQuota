# 原理与设计

> 部署步骤看 [`../README.md`](../README.md)，逐文件改动清单看 [`../CHANGES.md`](../CHANGES.md)。

## 1. 三条链路的分工

```
插件（如 ClinePassBridge）      宿主 CPA                      面板（本补丁）
  取数                          转发                          显示
  quota.describe 声明能力   →   /quota/providers 汇总     →   发现哪些 provider 有额度
  quota.fetch 向上游取数    →   /quota/fetch 代理调用     →   渲染 groups/buckets/summary
```

关键点：**宿主这一层是完整体**，缺的只有面板。所以本补丁不动 CPA 本体、也不动任何插件。

## 2. 为什么面板必须打补丁

### 2.1 宿主完整支持

`quota_provider` 是与 `auth_provider`、`model_provider` 平级的能力键。宿主实现了：

- `GET  /v0/management/quota/providers` —— 发现哪些 provider 支持额度
- `POST /v0/management/quota/fetch` —— 传 `auth_index`，provider 与插件由宿主解析
- `POST /v0/management/quota/reset`
- `GET  /v0/management/plugins/:id/quota`

### 2.2 面板是"一个厂商一份手写适配器"

内置的 7 个适配器是**借宿主的 `api-call` 代理直连厂商自己的接口**（Claude 打 Anthropic 的
usage 端点、Codex 打 OpenAI 的…），再用厂商专属解析器处理。因此：

```ts
// features/quota/providers/index.ts —— 静态查表，无回退
export const QUOTA_ADAPTERS: Record<QuotaProviderType, QuotaAdapter> = {
  antigravity: {...}, claude: {...}, codex: {...}, devin: {...},
  kimi: {...}, meta: {...}, xai: {...},
};
```

```ts
// features/authFiles/components/AuthFileQuotaSection.tsx —— 一串硬编码 if + 穷尽断言
const adapter = QUOTA_ADAPTERS[quotaType];
useQuotaStore((state) => { if (quotaType === 'claude') ... return assertNever(quotaType); });
```

```ts
// features/authFiles/logic.ts —— 白名单一票否决
if (!QUOTA_PROVIDER_TYPES.has(provider)) return null;
```

**宿主的 `/quota/fetch` 在面板里一个消费者都没有。** 这是架构缺口，不是配置问题。

### 2.3 不是版本问题

最新官方 release **v1.24.2（2026-09-22）** 的产物里检索：`quota/providers` = 0、
`credential/quota` = 0、`pluginQuota` = 0。**更新面板解决不了。**

## 3. 补丁的做法：一个通用适配器

不去逐个厂商写，而是加**一个**通用适配器 `plugin` 接宿主的通用端点：

```
GET  /v0/management/quota/providers   → 运行时发现（一次请求，失败也不阻塞页面）
POST /v0/management/quota/fetch       → { auth_index } 即可
渲染通用 groups[].buckets[] + summary[]
```

给封闭联合类型 `QuotaProviderType` 加第 8 个成员 `'plugin'`，让编译器把所有穷尽处理点报出来
（实际报出 5 处）—— 这是**安全的破坏式改动**，比把类型开放成 `string` 更不容易漏。

### 3.1 两条渲染入口都覆盖了

| 入口 | 位置 | 表现 |
|---|---|---|
| 认证文件卡片 | `AuthFileQuotaSection` | 卡片底部出现 **「点击此处刷新额度」**（文案即 `plugin_quota.idle`）|
| 配额管理页 | `QuotaPage` | 多出一个 **插件** tab（`auth_files.filter_plugin`）|

### 3.2 归类规则（容易写错的地方）

```ts
const isBuiltin = QUOTA_PROVIDER_TYPES.has(provider);
const isPlugin  = !isBuiltin && pluginProviders.has(provider);
if (!isBuiltin && !isPlugin) return null;
const quotaType = isBuiltin ? provider : 'plugin';
// 提供商 tab 的取值是【原始 provider key】，所以过滤要同时认 provider 与 quotaType
if (filter !== 'all' && filter !== provider && filter !== quotaType) return null;
```

踩过的坑：面板的 provider tab 取值是**原始 provider key**（例如 `cline-pass`），不是 `plugin`。
只判断 `filter !== 'plugin'` 会导致在那个 tab 下反而不显示。

### 3.3 宽容解析

- `GET /quota/providers` 的条目包装形状**未实证**（宿主是 `QuotaProviders(ctx)` 直出），
  解析器同时接受 `supported_providers` 字符串数组与"条目本身就是字符串"两种形态，
  并兼容 `display_name`/`displayName`、`supports_reset`/`supportsReset`。
- 额度桶双向兼容 `remainingFraction`/`remaining_fraction`、`resetTime`/`reset_time`、
  `display_name`，并**主动丢弃无效桶**（比例缺失或非有限数），与宿主的过滤规则一致。
- 发现结果 `load()` **失败也标记 `loaded`**：宿主没有插件额度时，不值得每次卡片渲染都重试。

## 4. provider 必须三处一致（最隐蔽的失败模式）

```
插件 quota.describe  →  supported_providers: ["cline-pass"]
宿主 /quota/providers →  {"providers": [ ... ]}
面板                 →  resolveAuthProvider(file) === "cline-pass" 才能匹配
```

三者必须是**同一个字符串**（大小写、连字符都要一致）。不一致的表现是
**不报错、也没有「点击此处刷新额度」按钮**，很难查。

## 5. 面板的缓存行为（"部署成功但界面没变"的根因）

CPA 返回面板时的响应头**只有 `Last-Modified`，没有 `Cache-Control`，也没有 `ETag`**。
浏览器对没有显式新鲜度信息的资源会启用**启发式新鲜度**（约为"距今时间 × 10%"）——
旧面板越久没更新，这个"不用回服务器问"的窗口越长，于是出现部署成功但打开还是旧界面。

对策见 [`../README.md`](../README.md) 的"两个必须注意的坑"。
根治是在反代给面板单独加 `add_header Cache-Control "no-cache" always;`。

## 6. 本仓库产物额外包含的两处显示层改动

本仓库根目录的 `management.html` 在"插件额度补丁"之上还含两处**纯显示层**改动
（都不影响额度能力，只是让某些插件的登录流程在面板里可用）：

1. **登录回调路由**（1 处）：面板原生的 `submitCallback` 只会把回调提交给宿主的
   `/v0/management/oauth-callback`，而宿主那条路**只读 `code`**。对回调里返回 `apiKey` 的
   供应商（如 Command Code），这条流程必然失败。补丁在 `submitCallback` 里加了一个分支：
   provider 解析为 `command-code` 时改投插件自己的 `/commandcodebridge/login/complete`。
2. **提示文案**（`oauth_callback_hint` 等，中文/英文本地化）：把"复制回调链接"的说明改成
   实际可操作的步骤（打开 F12 → Network → Payload 取表单数据），因为这类供应商的参数是
   以 POST 表单提交的，地址栏里看不到。

校验这两处是否在：

```bash
grep -o plugin_quota /tmp/served.html | wc -l                       # 期望 14
grep -o commandcodebridge/login/complete /tmp/served.html | wc -l   # 期望 1（不用 CommandCodeBridge 时可忽略）
```
